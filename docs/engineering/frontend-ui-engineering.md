## What it does

`frontend-ui-engineering` builds an interface that a person can use: keyboard, contrast, responsive layout, and a look that belongs to this product.

The defining constraint is that accessibility is part of the build, not a pass you schedule later. A page that only works with a mouse, or that looks like a generic template, is not done.

## When to reach for it

Type `/frontend-ui-engineering`, or the [agent](https://www.aihero.dev/ai-coding-dictionary/agent) reaches for it when a task fits.

## Usable

The leading word is **usable**. Name the keyboard path, the contrast, the small-screen layout, and the state a loading or empty page shows. Check the result in a browser when the change is visual.

## It's working if

- A keyboard user can complete the action.
- The layout is specific to the product, and empty and loading states are designed.

## Where it fits

This is a **reach-for-it-anytime standalone** on the UI branch of a build.

Its neighbour is [browser-testing-with-devtools](https://aihero.dev/skills-browser-testing-with-devtools), because a usable page still has to be looked at in a real browser.
